# ADR 0010: 1.0 API stability and versioning policy

- Status: Accepted
- Date: 2026-11-14
- Deciders: Abolfazl Ranjbaran
- Extends: [ADR 0001](0001-sync-first-core.md),
  [ADR 0006](0006-async-execution-model.md)
- Related: [ADR 0003](0003-packaging-and-publishing.md),
  [ADR 0004](0004-pypi-distribution-name.md),
  [ADR 0009](0009-streaming-responses.md)

## Context

The 0.x series moved fast: nine minor releases in two weeks shipped the
async layer, three vendor wire formats and streaming. The README honestly
said "Actively developed, pre-1.0", and the top-level package exported a
deliberately minimal 9-name facade (`Agent`, `AgentResult`, `AsyncAgent`,
`AsyncRuntime`, `Runtime`, `Settings`, and the three runtime factories).
Everything else — the `Provider` contract, the tool layer, the typed
errors, the offline testing providers — was reachable only through
submodule imports (`nexusagent.provider`, `nexusagent.tool`, ...), which
the examples and guides all use.

That served a pre-1.0 codebase well: the surface could grow without
ceremony. But the core contracts have now been stable across many
releases, every layer is contract-tested, the suite sits at 1103 tests
with 99.85% coverage, and the honest gaps (memory, orchestration,
retries) are explicitly scoped as future work with their own ADRs. The
prerequisite for callers to build on NexusAgent is a declared, enforced
API stability contract.

## Decision

**1.0.0 declares API stability under Semantic Versioning, with the
package root (`nexusagent/__init__.py`) as the complete, versioned public
surface.**

- **The public API is exactly `nexusagent.__all__`.** The facade grows
  from the minimal 9 names to the full 33-name contract: the Agent layer
  (`Agent`, `AgentResult`, `AsyncAgent`, `Runtime`, `AsyncRuntime`), the
  runtime factories (`create_runtime`, `create_async_runtime`,
  `create_application_runtime`, `create_provider`), `Settings`, the
  Provider contract (`Provider`, `AsyncProvider`, `ProviderConfig`,
  `TextResponse`, `ToolCallRequest`, `StreamTextDelta`,
  `ProviderResponse`, `ProviderStreamEvent`, `ToolSpec`, `ToolResult`),
  the tool layer (`Tool`, `AsyncTool`, `ToolRegistry`, `ToolExecutor`,
  `AsyncToolExecutor`), the offline testing providers (`FakeProvider`,
  `ScriptedProvider`), the sync-in-async bridge (`SyncProviderAdapter`)
  and the typed errors (`ProviderError`,
  `ProviderConfigurationError`, `ProviderRequestError`,
  `ProviderResponseError`, `ToolExecutionError`). Every name is
  importable as `nexusagent.<name>`; every existing submodule import
  keeps working unchanged.
- **SemVer commitment.** Within major version 1, nothing in `__all__` is
  renamed, moved or removed; additions are minor versions; fixes are
  patches. Removing or changing the behavior of a public name requires
  major version 2, preceded by a deprecation release that documents the
  replacement in the CHANGELOG.
- **What stays internal.** The vendor wire adapters
  (`HttpProvider`, `OpenAIProvider`, `AnthropicProvider`,
  `GeminiProvider`), the built-in demo tools (`EchoTool`,
  `UppercaseTool`, `CalculatorTool`) and the internal factories
  (`create_tool_registry`, `create_tool_runtime`) are deliberately not
  re-exported at the root: adapters are constructed through
  `create_provider()` or `Settings`, tools through subclasses of the
  public `Tool` ABC. Direct submodule imports remain possible, but only
  the root surface is guaranteed.
- **The surface is pinned by tests.** `tests/test_public_api.py` pins
  `__all__` exactly (contents and order), verifies every name resolves
  at the root, verifies every export is defined inside the package
  (union-type aliases resolve to their member classes), and pins the
  `MAJOR.MINOR.PATCH` version format. An accidental removal, rename or
  silent addition fails CI. The former 9-name pins in
  `tests/test_init.py` follow the new policy; the no-construction rule
  for `__init__.py` (architecture rule) is unchanged.
- **Zero runtime dependencies is part of the contract.** `pip install
  nexusagent-runtime` pulls nothing beyond the standard library, as it
  has since the first release (ADR 0003).
- **Python support.** Python 3.10–3.13 (matching `requires-python`);
  support follows the published matrix in the README.

## Consequences

- Callers can build on NexusAgent with a version pin and a stable import
  story; the README status section no longer says "pre-1.0".
- `docs/concepts.md` documents the root surface as the reference; the
  guides keep showing top-level imports for everything public.
- The distribution, import name and PyPI arrangement (ADR 0004) are
  themselves covered by this contract.
- The honest remaining gaps (memory/planning/orchestration, HTTP
  retries, further vendor adapters) stay future work under their own
  ADRs — stability means the existing contracts do not move, not that
  development stops.
